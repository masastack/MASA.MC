## ADDED Requirements

### Requirement: 模板发放必须保留模板审计元数据
系统 SHALL NOT 在模板消息发放流程仅读取模板来创建或发送消息时，更新被引用消息模板的修改人或修改时间。

#### Scenario: 内部模板消息发放
- **WHEN** 内部调用方通过渠道编码和模板编码发放模板消息
- **THEN** 系统创建对应的模板消息任务
- **AND** 被引用消息模板的修改人和修改时间保持不变

#### Scenario: 外部模板消息发放
- **WHEN** 外部调用方通过渠道编码和模板编码发放模板消息
- **THEN** 系统按现有规则创建模板消息任务或 simple-send job
- **AND** 被引用消息模板的修改人和修改时间保持不变

#### Scenario: simple-send 模板消息发放
- **WHEN** 调用方通过模板编码发放 simple-send 模板消息
- **THEN** 系统使用渲染后的模板数据发布 simple message event
- **AND** 被引用消息模板的修改人和修改时间保持不变

### Requirement: 模板发放仍需校验引用模板
系统 MUST 保持现有的模板存在性校验行为。

#### Scenario: 模板不存在
- **WHEN** 模板消息发放流程引用了不存在的模板编码或模板 id
- **THEN** 系统按现有消息模板不存在行为失败
- **AND** 不会基于缺失模板创建消息任务

### Requirement: 模板发放保留模板派生数据
系统 SHALL 继续把只读模板数据复制到消息任务或消息事件中。

#### Scenario: 模板数据复制到消息任务
- **WHEN** 模板消息发放流程基于已有模板创建消息任务
- **THEN** 任务仍然得到预期的模板实体 id、展示名、签名、消息类型和站内信标记
- **AND** 读取这些值不会把源模板标记为已修改

#### Scenario: 发送事件处理器使用模板数据
- **WHEN** 模板发送事件处理器读取模板做发送上限校验、退订校验、变量转换、内容渲染或供应商请求组装
- **THEN** 处理器保持现有发放行为
- **AND** 读取模板不会把源模板标记为已修改
